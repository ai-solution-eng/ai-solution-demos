rag-mcp-server {{ .Chart.Version }} (app {{ .Chart.AppVersion }}) deployed to namespace {{ $ns }}.

════════════════════════════════════════════════════════════════════
1. REST API key — AUTO-GENERATED per install (the chart ships no key
   material; P0-7, 2026-09). Every /api/* call needs it (X-RAG-Api-Key
   or Authorization: Bearer), except health probes and the served pages
   (the served page embeds it for the browser console; the ingress
   oauth2 layer is the real boundary there). Retrieve it:

  kubectl -n {{ $ns }} get secret {{ $name }}-model-keys \
    -o jsonpath='{.data.RAG_API_KEY}' | base64 -d; echo

   Upgrades KEEP the generated value (the chart reuses the released
   Secret — never rotated under a running deployment). To supply your
   own keys instead: --set security.existingSecret=<your-secret> (keys
   RAG_API_KEY + MEDIA_TOKEN_SECRET), or inline security.apiKey /
   security.mediaTokenSecret (back-compat). Rotating is OPTIONAL and
   operator-initiated — read helm/ROTATION.md first (rotated keys and
   existing media tokens stop working).

2. MCP API key — OPTIONAL (auth is OFF until you enable it).
   The MCP endpoints run OPEN
   until you enable the key gate. To enable — the chart NEVER inlines a
   key in values:

  kubectl -n {{ $ns }} create secret generic rag-mcp-apikey \
    --from-literal="api-keys=$(openssl rand -hex 32)" \
    --dry-run=client -o yaml | kubectl apply -f -
  helm upgrade <release> . -n {{ $ns }} --reuse-values \
    --set mcp.apiKey.existingSecret=rag-mcp-apikey

   ROTATION (zero downtime once enabled): the value is a
   COMMA-SEPARATED list of valid keys — append the new one, move
   clients over, drop the old. The server re-reads the env per request
   — no restart needed. The fleet-universal MCP_API_KEYS env is honored
   too (either var works).
{{- if $modelSecret }}

2b. Model API keys — provided by YOUR Secret (modelSecrets.existingSecret =
    {{ $modelSecret }}). Every MODEL_*/S3_*/REDIS_PASSWORD key it carries
    overrides the chart-managed {{ $name }}-model-keys Secret (wired last in
    envFrom and CONFIG_DIR); keys it omits keep the seeded/stored values.
    Rotation is kubectl/ESO-native and hot-reloads (<=15s, no rollout).
    Endpoints may live there too (MODEL_<ROLE>_URL overrides the ConfigMap).
    The values modelSecrets.* seeds are now optional fallbacks — safe to
    blank (do NOT delete the {{ $name }}-model-keys object itself).
{{- else }}

2b. Model API keys — seeded from values (modelSecrets.*) into the
    {{ $name }}-model-keys Secret. To keep key material out of values
    entirely, create your own Secret with the canonical key names
    (MODEL_EMBEDDER_API_KEY, MODEL_RERANKER_API_KEY, MODEL_VLM_API_KEY,
    MODEL_ASR_API_KEY — optionally MODEL_*_URL endpoints, S3_*,
    REDIS_PASSWORD) and re-run:
      helm upgrade <release> . -n {{ $ns }} --reuse-values \
        --set modelSecrets.existingSecret=<your-secret>
    Missing Secret = pods fail loudly (CreateContainerConfigError).
{{- end }}
